## 1. The problem statement in plain words

**Given:** one flat top-down photo (satellite or drone). No stereo pair, no LiDAR.

**Produce:** how tall everything is (buildings, trees, hills), then let a person **fly through it in 3D**.

Two kinds of input, two kinds of output:

| Input     | Has location metadata? | Output                                                                               |
| --------- | ---------------------- | ------------------------------------------------------------------------------------ |
| PNG / JPG | No                     | **Relative** DSM — heights with no georeference and no link to a real map            |
| GeoTIFF   | Yes                    | **Absolute** DSM — real elevation above sea level, calibrated with SRTM 30 m terrain |

**How it is graded (50 / 50):**

- **50% DSM accuracy:** RMSE, MAE, correlation against LiDAR/reference, across urban, sparse, hilly, forested scenes. _(ML team.)_
- **50% visualization:** projection accuracy, visual fidelity, navigability of the flythrough, interface intuitiveness, stability, standalone deployment. **(You.)**

The PS also explicitly asks the platform to let users _upload imagery, visualize terrain, and validate height values against reference datasets_, and to support _analysis of structural heights and slopes from arbitrary aerial perspectives_. Those sentences are the checklist for your viewer, and every one of them is built into the code below.

## 2. The overall solution

```
 PNG/JPG/GeoTIFF
       │
       ▼
┌────────────────────┐   ┌───────────────────────┐   ┌──────────────────────────┐
│ Part 1: Depth      │──▶│ Part 2: Calibration   │──▶│ Part 3: Visualizer (YOU) │
│ Anything V2        │   │ (GeoTIFF only)        │   │ upload → data → flythrough│
│ fine-tuned on GAMUS│   │ SRTM → absolute metres│   │                          │
└────────────────────┘   └───────────────────────┘   └──────────────────────────┘
  ML team (Krishna/Prasun)                               Ashutosh
```

**What Part 1 actually outputs now** (from the ML team's README): a per-pixel **height above local ground (AGL) in metres**, as `height_agl.npy` (518×518, float32), plus `rgb.png` (the texture, same size), `metadata.json`, and some preview PNGs. Earlier in our discussion I described the model output as "unitless relative depth". Their export is already metric AGL, so the viewer labels it **AGL (m)**, not "relative". "Relative mode" in this app means _non-georeferenced_ (no absolute elevation, no real pixel size), not _unitless_.

**Part 2 later** replaces the meaning of the numbers: `absolute_elevation = terrain_elevation + AGL`. Array shape and dtype stay the same. Your renderer must therefore read a generic elevation array plus a `vertical_reference` string, never hard-code "AGL". That is exactly how this app is built.

**Where you differentiate (from earlier planning), and what is in this build:**

| Idea                                                                | Where it lives                   | Status                    |
| ------------------------------------------------------------------- | -------------------------------- | ------------------------- |
| Landscape-aware calibration                                         | ML team (Part 2)                 | not your code             |
| Interactive click-to-recalibrate                                    | `Recalibrate` panel              | ✅ built                  |
| Validate against a reference `.npy` (RMSE/MAE/r + error heat-layer) | `Validate` panel                 | ✅ built                  |
| Slope overlay, height colormap, two-point measure                   | Layers + Probe panels            | ✅ built                  |
| Fly **and** walk modes, minimap, auto tour, screenshot              | Navigator/HUD                    | ✅ built                  |

## 4. Research: how to turn a height array into a good 3D scene

You asked for "the best way to do the 3D conversion". Here are the options, and why the code uses the one it does.

| Approach                                   | What it is                                                                            | Verdict                                                                                                                                                      |
| ------------------------------------------ | ------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| **CPU-built displaced grid mesh (chosen)** | One vertex per pixel; write Y from the height array; analytic normals; RGB as texture | Exact control, works with raycasting/walk collision because the same array is in JS memory. 518² = 268k vertices, 535k triangles: trivial for any modern GPU |
| GPU vertex-shader displacement             | Send the height as a texture; displace in the vertex shader                           | Fast slider changes, but then CPU picking, walk-mode ground following and slope readouts need a second copy of the data anyway. No gain at this tile size    |
| Point cloud                                | One point per pixel                                                                   | Looks noisy and unfinished; poor for judges                                                                                                                  |
| Extruded boxes (Git City style)            | One box per building                                                                  | Needs per-building segmentation. We have a height _field_, not building footprints                                                                           |
| CDLOD / geoclipmaps, Cesium terrain tiles  | LOD terrain for planet-scale data                                                     | Massive overkill for a single 518² tile                                                                                                                      |
| Unity / Babylon                            | Alternative engines                                                                   | Unity's build/export overhead is a poor fit for a 2-day hackathon; Three.js + R3F gives a web app with zero install                                          |

**Why not fork Git City:** it renders _instanced boxes from database rows_, a different geometry model than a continuous heightfield, so ~90% of it would be deleted. Its license is also AGPL-3.0, which obliges you to publish source for public deployments. Instead the app copies the _feel_ of a Git City flight (mouse-look, WASD, vertical keys, shift boost, damped velocity) in a small custom controller. (I could not open Git City's `src/` — GitHub blocked automated access — so nothing here depends on its internals.)

**Known limitation of any heightfield ("2.5D"), and the mitigations built in:**

1. _Walls are ramps._ Between a rooftop pixel and a ground pixel the mesh has a steep face. **Mitigation:** full-resolution mesh (stride 1), plus optional smoothing.
2. _The top-down texture stretches on steep faces._ **Mitigation:** "Wall shading" darkens vertices whose slope is above ~45° so the stretched texture reads as a wall rather than as a smear.
3. _No undercuts_ (overhangs, tree trunks). Unfixable from a height field; do not promise them.
4. _Model noise is visible in 3D._ **Mitigation:** the Smoothing slider (box blur, 0–4 px). Metrics deliberately exclude smoothing so nobody can claim a better RMSE by blurring.
5. _Horizontal scale is unknown for non-georeferenced input._ Heights are metres but pixel spacing is not. **Mitigation:** an "assumed pixel size" slider (default 1 m/px), clearly labelled as an assumption; slopes and distances depend on it. For GeoTIFF the pixel size comes from metadata and the slider locks.

**Coordinate convention (1 world unit = 1 metre):** `+Y` up, image top = north = `−Z`, image left = west = `−X`, image centre = origin. `x = (col − (w−1)/2)·pixel`, `z = (row − (h−1)/2)·pixel`, `y = (elevation − baseline)·exaggeration`. In absolute mode `baseline = min(elevation)` so a 1200 m-high scene still sits near y = 0 (readouts add the real elevation back).

**Fly-through UX conventions used:** Pointer-Lock mouse-look (standard for first-person), WASD + Q/E, Shift boost, mouse-wheel speed, exponential velocity smoothing, terrain clamping so you cannot fly into the ground, **walk mode** that follows the ground at eye height, a **crosshair readout** (height/slope/distance of what you are looking at), a **minimap** (click to teleport), an **auto-tour** for demo videos, **H to hide the HUD** for clean recordings, and a **screenshot** button for your PPT.

**Slope caveat (say this if a judge asks):** slope is computed from the _displayed surface_ (AGL + terrain). On a building wall it reports the wall's steepness, not the terrain's. It is a surface slope, not a bare-earth slope.

## 5. Architecture and the contract (relative vs absolute, kept separate from day one)

```
Browser (Vite + React + R3F)                    FastAPI (dummy now, real later)
────────────────────────────                    ───────────────────────────────
POST /api/jobs  (file  or  ?sample=png|tif) ──▶  save upload, create job, return job_id
GET  /api/jobs/{id}  (poll every 450 ms)    ──▶  { status, stages[], stage_index, result? }
GET  result.files.rgb / elevation /
     metadata / terrain?                    ──▶  static files from data/results/{id}/
```

**The job result is the contract** (`frontend/src/types.ts` mirrors it):

```json
{
  "input_kind": "png | jpg | geotiff",
  "mode": "relative | absolute",
  "original_filename": "tile.png",
  "dummy": true,
  "files": {
    "rgb": "/api/results/ID/rgb.png",
    "elevation": "/api/results/ID/height_agl.npy",
    "metadata": "/api/results/ID/metadata.json",
    "terrain": null
  }
}
```

**Who decides relative vs absolute?** The backend, by input type, via `mode`. The frontend never guesses from the file extension.

|                               | Relative (PNG/JPG)   | Absolute (GeoTIFF)                                                    |
| ----------------------------- | -------------------- | --------------------------------------------------------------------- |
| `mode`                        | `relative`           | `absolute`                                                            |
| `elevation` file holds        | AGL metres           | elevation above sea level, metres                                     |
| `metadata.vertical_reference` | `AGL`                | `absolute_elevation`                                                  |
| `terrain` file                | none                 | bare-earth elevation (needed for structure height and recalibration)  |
| Pixel size                    | **assumed** (slider) | from `metadata.pixel_size_m` (slider locks)                           |
| CRS                           | none                 | `coordinate_reference_system`                                         |
| Probe shows                   | AGL, slope           | elevation ASL, structure height, terrain elevation, slope             |
| Recalibrate                   | yes                  | yes if `terrain` present, otherwise disabled                          |
| Validate vs reference         | vs an AGL reference  | vs AGL (needs terrain) or vs an absolute reference                    |
| Pipeline steps shown          | 5 steps              | 6 steps (adds _Reading georeference_, _Fetching SRTM_, _Calibrating_) |

If backend `mode` and metadata `vertical_reference` disagree, the Processing screen shows a warning card instead of silently picking one.

### 9.3 Swapping the dummy for the real pipeline (exact diff instructions)

You change only `backend/app/main.py`. The frontend does not change.

**Step 1 — remember the uploaded file's path.** In `create_job`, inside the `if file is not None ...` branch, after the `with open(...)` block, add `upload_path = d / Path(file.filename).name`; set `upload_path = None` in the `elif sample` branch; then add one key to the `JOBS[job_id] = {...}` dict:

```python
        "upload_path": str(upload_path) if upload_path else None,
```

**Step 2 — pass it to the builder.** In `run_job`, change the call to:

```python
files = await asyncio.to_thread(build_package, job_id, job["kind"], job.get("upload_path"))
```

**Step 3 — replace the body of `build_package`.** New signature: `def build_package(job_id: str, kind: str, upload_path: str | None) -> dict`. It must write these files into `RESULTS / job_id` and return their names:

| Input kind | Files to write                                                             | Return value                                                                                                              |
| ---------- | -------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------- |
| PNG / JPG  | `rgb.png`, `height_agl.npy`, `metadata.json`                               | `{"rgb": "rgb.png", "elevation": "height_agl.npy", "metadata": "metadata.json", "terrain": None}`                         |
| GeoTIFF    | `rgb.png`, `height_absolute.npy`, `terrain_elevation.npy`, `metadata.json` | `{"rgb": "rgb.png", "elevation": "height_absolute.npy", "metadata": "metadata.json", "terrain": "terrain_elevation.npy"}` |

**Step 4 — set `"dummy": True` → `False`** in `run_job` (this removes the orange DEMO DATA badges).

**Step 5 (optional but recommended) — make progress real.** The dummy sleeps through fixed stage names. Have your pipeline update `job["stage_index"]` as it moves between real stages; the UI already renders whatever `stages` list you return, so you can rename them.

**Hard requirements for the files** (send this to the ML team):

1. `.npy` arrays: **float32, C-contiguous, little-endian**, shape `(H, W)`, in **metres**, all the same shape as `rgb.png`. (float64/int16/uint16/uint8 also parse, but float32 is the contract.)
2. `rgb.png` must be the same H×W as the arrays (otherwise the texture is stretched and a warning card appears).
3. For GeoTIFF/absolute: `metadata.json` must contain `vertical_reference: "absolute_elevation"`, `georeferenced: true`, `coordinate_reference_system`, and `pixel_size_m` (metres per pixel; the viewer uses it for real slopes and distances). `bounds` (`[minx, miny, maxx, maxy]`) and `terrain_source` are optional and shown in the Dataset panel.
4. Use `NaN` for invalid pixels if any; the viewer and the metrics ignore non-finite values (the mesh treats a NaN height as broken geometry, so prefer filling with 0).

**Questions to ask the ML team (their answers change small things):**

## 10. How navigation works (fly, walk, tour, probe)

| Input                           | Action                                                       |
| ------------------------------- | ------------------------------------------------------------ |
| **F** or the _Capture_ button   | Lock the mouse (Pointer Lock). **Esc** releases              |
| Mouse (locked)                  | Look around                                                  |
| Drag (not locked)               | Look around (fallback if Pointer Lock is blocked)            |
| **W A S D**                     | Move forward / left / back / right                           |
| **Q / E** (or **Space** for up) | Down / up (fly mode)                                         |
| **Shift**                       | 3× speed boost                                               |
| Mouse wheel                     | Scale speed (3–400 m/s), mirrored in the Speed slider        |
| **V**                           | Toggle **Fly ↔ Walk**                                        |
| **T**                           | Toggle the automatic orbit **Tour** (any key/click stops it) |
| **R**                           | Reset camera to the overview shot                            |
| **H**                           | Hide/show the HUD (for clean screen recordings)              |
| **M**                           | Toggle minimap · click the minimap to **teleport**           |
| **1 / 2 / 3 / 4** or **L**      | Layers: RGB / Height / Slope / Error (4 needs a reference)   |
| Click terrain (not locked)      | Drop probe **A**, then **B**, then it restarts at A          |
| Click while locked              | Drop a probe at the crosshair                                |

**Fly mode:** free 3D movement in the look direction; the camera cannot go below `ground + 2 m` and may drift up to 30% of the tile size beyond the edges.

**Walk mode:** movement is horizontal only; the camera height follows the terrain surface smoothly at your eye height (default 1.8 m, adjustable). Walk speed is 10% of fly speed (clamped 2–30 m/s). Walking onto a rooftop makes you climb it, because the surface _is_ the roof. That is the honest behaviour of a DSM.

**Crosshair readout (mouse captured):** every third frame a ray is marched against the heightfield (12-step bisection refinement) and the label shows height/elevation, slope, and distance of whatever you are looking at.

**Measure:** points A and B give horizontal distance and Δ height (B − A). Horizontal distance uses the pixel size (assumed in relative mode, real in absolute mode).

**Recalibrate (your demo moment):** drop a probe on something whose real height you know (say a 12 m building), type `12`, press Apply. The scale factor is `known / predicted` at that point; the whole surface rescales live and the metrics update if a reference is loaded. Guarded: refuses points where predicted height < 0.5 m (ground) and clamps the factor to 0.05–20×. In absolute mode only the structure part is scaled; terrain elevation is untouched.

**Validate:** _Load .npy_ with a ground-truth height array. It is resized (bilinear) to the dataset grid, then RMSE, MAE, correlation r and bias appear, and the **Error layer** is enabled (blue = under-estimate, red = over-estimate, clipped at the 95th-percentile error). Metrics use the calibrated prediction with smoothing excluded. To test without real reference data:

```bash
python - <<'EOF'
import numpy as np
a = np.load("backend/reference/height_agl.npy")
np.save("fake_ref.npy", (a + np.random.normal(0, 1.5, a.shape)).astype("float32"))
EOF
```

Loading `fake_ref.npy` should give RMSE ≈ 1.5 m and r ≈ 0.98+. If it does, the validation panel is working.

## 13. Known issues and honest limits

- **Not visually tested by me** (see Section 0). Expect small tuning of shadows/exaggeration on first run.
- The JS bundle is ~1.2 MB (Three.js). Fine for a demo, unimportant on localhost.
- The dummy "absolute" data is fake (a synthetic terrain plus your AGL). Never present it as real calibration. The DEMO DATA badge exists so nobody mistakes it.
- A heightfield cannot show undercuts or wall textures (Section 4).
- Slope is a surface slope (Section 4).
- Recalibration is a single global multiplier, not per-landscape-class calibration (that is the ML team's Part 2 differentiator).
- The Dockerfile is untested.
- GeoTIFF _reading_ happens on the backend (real Part 2). The frontend never parses TIFF.

## 15. If something breaks

| Symptom                                                 | Cause / fix                                                                                                        |
| ------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------ |
| "Cannot reach the backend. Is it running on port 8000?" | Start uvicorn; in dev the Vite proxy forwards `/api` to `localhost:8000`                                           |
| Blank page                                              | Open the console. An error boundary card normally shows; if not, it is a module import error: re-run `npm install` |
| `Unsupported .npy dtype`                                | The array is not float32; re-save with `arr.astype("float32")`                                                     |
| `Fortran-ordered .npy is not supported`                 | Save with `np.ascontiguousarray(arr)`                                                                              |
| `Expected a 2-D height array`                           | Array has extra dimensions; squeeze to `(H, W)` (a leading or trailing 1 is accepted)                              |
| Texture stretched warning                               | `rgb.png` size ≠ array size; resize the PNG to the array's H×W                                                     |
| Mouse will not capture                                  | Browser blocked Pointer Lock: click the canvas first, use `localhost` or HTTPS, and note Esc releases it by design |
| Everything is flat                                      | Exaggeration too low or pixel size too large; try ×3 and pixel size 0.5                                            |
| Everything is spiky                                     | Exaggeration too high or pixel size too small                                                                      |
| Absolute mode: Recalibrate greyed out                   | No `terrain` file in the package (structure height unknown)                                                        |
| `tsc` errors after upgrading packages                   | Use the exact versions in Section 8.1                                                                              |
